# OSI Model

**Date:** 2026-10-03

## What it is

The OSI (Open Systems Interconnection) model is a 7-layer conceptual framework that describes how data travels from one device to another across a network. Each layer has one job and talks only to the layers directly above and below it. It is a reference model, which makes it very useful for troubleshooting and for describing where an attack or a fault happens.

## The 7 layers (top to bottom)

| # | Layer | What it does | Examples | Data unit (PDU) |
|---|-------|--------------|----------|-----------------|
| 7 | Application | Interface between the network and the user's software | HTTP, HTTPS, DNS, SMTP, FTP | Data |
| 6 | Presentation | Translates, encrypts, and compresses data | TLS/SSL, JPEG, ASCII | Data |
| 5 | Session | Opens, manages, and closes sessions between devices | NetBIOS, RPC, session tokens | Data |
| 4 | Transport | End-to-end delivery, segmentation, reliability, ports | TCP, UDP | Segment (TCP) / Datagram (UDP) |
| 3 | Network | Logical addressing and routing between networks | IP, ICMP, routers | Packet |
| 2 | Data Link | Physical addressing and delivery within one local network | Ethernet, MAC addresses, switches | Frame |
| 1 | Physical | Moves raw bits over a medium | Cables, Wi-Fi radio, hubs | Bits |

Memory trick (top to bottom): **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing.

## Encapsulation

When sending data, each layer adds its own header (and sometimes a trailer) around the data from the layer above it. This wrapping process is called **encapsulation**.

1. Application, Presentation, and Session layers produce the **data**.
2. Transport adds a TCP/UDP header (source and destination ports), creating a **segment**.
3. Network adds an IP header (source and destination IP addresses), creating a **packet**.
4. Data Link adds a header with MAC addresses and a trailer (FCS for error checking), creating a **frame**.
5. Physical converts the frame into **bits** (electrical, light, or radio signals).

The receiving device does the reverse, called **de-encapsulation**: each layer strips its own header and passes the contents up until the application receives the original data.

## Why it matters for a SOC analyst

- Alerts and attacks map to layers: ARP spoofing (Layer 2), IP spoofing and ICMP floods (Layer 3), SYN floods and port scans (Layer 4), phishing and SQL injection (Layer 7).
- Troubleshooting works best bottom-up: check the cable or Wi-Fi first, then addressing, then ports, then the application.
- Knowing which layer a security tool works at (for example a firewall vs. a web application firewall) tells me what it can and cannot see.

## Still to practice

- Watch a real packet in Wireshark and identify each layer's header.
